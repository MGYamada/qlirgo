# qlirgo working guidelines

- The stable candidate is qlirgo 0.2.0 and targets exact Qleisli 0.3.0. Before Qleisli publication qualify the pinned candidates using an isolated local link. Registry lockfiles, clean installation, official host and extraction checks precede formal publication after Qleisli is available. Follow docs/releasing.md and preserve previously published artifacts.
- Follow QRATEBOUNDARY.md: every internal or external qrate has an independent environment boundary, including its Rust development environment when present. qlinties, qlifmt, and qlidoc are three ordinary qrates; align their versions with qlirgo only for bundle convenience, without privilege. Only std has the reserved bundled distribution identity, versioned alongside Qleisli; its bodies retain ordinary independent checking. Follow docs/qrate-development.md for the independent Cargo environments and extraction verification.
- For extraction work, enforce the shared-support/linter API separation, wiring-only root adapters, and the acyclic qlirgo-to-components dependency direction in QRATEBOUNDARY.md. Bind the complete Rust project inventory and actual build environment separately from existing Qleisli source/qrate input identities. Root Cargo [package].version is the release-orchestration authority; Rust component manifests retain the full literal product version; bundled qrate manifests retain the canonical three-part base, both validated against it.
- Follow docs/architecture.md: Exact, Immutable, Bound, Explicit, Independent. Keep typed requests, immutable captured subjects, checked/validated results, and explicit effects separate. Bind results to actual input/tool identities; publisher authentication belongs to distribution policy, and metadata is not mathematical evidence.
- Qlirgo manages Qleisli qrates; Cargo builds, packages, and installs the Rust implementation outside qlirgo operations. Never invoke Cargo from a qlirgo command or translate qlirgo test/doc into Rust tests/Rustdoc.
- Legacy qargo started crates.io distribution with 0.1.1. The new standard bundle is prepared under package name qlirgo alongside GitHub source releases, installing all four executables. The public package compiles the canonical qrate sources as internal modules; private engine crates remain development-only. A source-archive check does not establish .crate packaging readiness. Validate the packaged sources and installation before publication; version preparation does not authorize publishing.
- Starting with 0.1.5, also distribute native Linux x86_64 and macOS x86_64/ARM64 binary archives, install.sh, and SHA256SUMS. Published 0.1.9 retains the Qleisli 0.2.1 Linux ARM64 deferral (issue #18); the new linked target needs fresh host validation. Validate archive inventory, platform linkage, and Cargo-free installation independently. These are implementation distribution operations outside qlirgo commands; binary assets require explicit GitHub release authorization before publication.
- The standard bundle comprises qlinties, qlifmt, and qlidoc, prepared at Rust product version 0.2.0, with literal bundled qrate base version 0.2.0. Full Rust versions must match for tool transport. Each qrate includes its Rust engine, CLI, Rust test sources, and a minimal src/smoke.qli management sample, with no .qlt files. Keep shared Rust source in tool-support/ outside all three qrates. Each engine must build, test, and run without either peer, its source tree, or its Cargo package. Developer Cargo configuration lives outside the qrates in independent rust/<tool>/ workspaces with their own lockfiles and toolchain declarations. Transfer only the selected qrate and Rust workspace, the neutral support sources, and the selected registry closure during extraction. Use source strings and temporary directories for engine tests; preserve coverage of empty qrate roots.
- Full independent extraction verification is an on-demand workflow, not a push/PR check. Require its complete Linux/macOS × Rust 1.85/stable matrix for every release candidate. Ordinary CI retains lightweight boundary audits and source/package validation; it does not replace the manual release gate.
- Read docs/specification.md before changing public behavior. Manifest and result schema versions are independent of product versions.
- Valid Qlirgo.toml manifests, documentation examples, and test fixtures must use schema-version = 2 and explicitly declare edition = "2026" under [qrate]. Never omit or infer the Qleisli edition, supply a default, or accept an unsupported edition. Qleisli and Rust editions are independent; keep the Rust implementation's Cargo.toml edition = "2024" explicit.
- Preserve ordinary Qleisli checking and its trust boundary. Empty source roots have no Qleisli checking result. Lint results and build records are metadata, not mathematical evidence.
- Follow docs/ecosystem-policy.md: curated stdlib first; future extensions require trusted sources, authenticated namespaces, and fixed identities. Public registry and automatic semver resolution are deferred. Never introduce arbitrary qrate build hooks, native procedural macros, dependency-install scripts, or global feature unification into qlirgo operations. Rust implementation builds remain outside that boundary.
- Follow docs/adoption-plan.md for tooling work: local diagnostic explanations, compatibility comparisons, explicit documentation-example checks, then scoped review records. Toolchain selection, structured repairs, and QLT execution require their upstream protocols and separately specified public contracts; the plan does not implement them or authorize changing the Qleisli dependency pin.
- Follow docs/toolchains.md for qleisliup compatibility. Start with offline proxy/bundle checks; qleisliup selection does not replace the linked Qleisli checker. Do not parse human manager output, couple qlirgo to manager state or a qleisliup library, or treat a repository toolchain pin as captured acceptance configuration before its qlirgo contract is specified.
- qlifmt and qlidoc use syntax parsing only; their success does not imply type, ownership, or contract verification. qlidoc currently generates Markdown; future HTML may use independent CSS and layout rather than rustdoc's appearance.
- Specifications, public documentation, diagnostics, and code comments are English. User conversation can follow the user's language.
- Use lowercase `qlirgo` for the product name except at the beginning of a sentence; preserve literal filenames such as `Qlirgo.toml` and `Qlirgo.lock`.
- Rust 1.85 is the MSRV; forbid unsafe code. Preserve the immutable beta and historical 0.2.1 package records.

- The linked beta migration is recorded in docs/linked-qleisli-030.md. The stable candidate retains captured configuration, the actual std pairing, parent schemas 2 and child schemas 1, and explicit matching native acceptance.
